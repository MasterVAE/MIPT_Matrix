# MIPT Matrix

Библиотека квадратных матриц и консольная программа для вычисления определителя.
Размер задаётся во время выполнения. ArrayMatrix<T> хранит элементы в одном
векторе, JaggedMatrix<T> — в векторе строк. Общий интерфейс Matrix<T> / IMatrix<T>:
Size(), At(row, col), Determinant().

## Требования

- Linux или WSL, GCC 10+ либо Clang 12+ с поддержкой C++20.
- CMake 3.16+ и средство сборки (например, GNU Make).
- Python 3.10+ для E2E-тестов (без сторонних Python-пакетов).

Google Test и доступ к сети не нужны. MSVC не поддерживается:
проверка переполнения использует встроенные функции GCC/Clang.

## Сборка

Из корня проекта:

~~~sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
~~~

Исполняемый файл: build/matrix_cli. Только программа, без тестов:

~~~sh
cmake -S . -B build-cli -DBUILD_TESTING=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build-cli --parallel
~~~

## Запуск

~~~sh
printf '1 2 3 4\n' | ./build/matrix_cli array int 2
# -2
printf '0.5 1.5 2 3\n' | ./build/matrix_cli jagged double 2
# -1.5
~~~

Формат: matrix_cli <array|jagged> <int|longlong|float|double> <n>.
В stdin передаются n*n чисел построчно. В stdout печатается определитель.
Размер 0 допустим, определитель пустой матрицы равен 1.
Ошибки выводятся в stderr: код 1 — неверные аргументы, 2 — ошибка чтения
элементов, 3 — исключение при создании матрицы или вычислении.

Для целых используется алгоритм Барейса с расширенными промежуточными значениями
и проверками переполнения; если промежуточные значения или результат не помещаются
в соответствующий тип, выбрасывается std::overflow_error. Это не арифметика
произвольной точности. Для вещественных типов используется метод Гаусса
с частичным выбором ведущего элемента; результат приближённый.

At использует индексы от 0 до Size()-1; проверка границ не выполняется.
Конструкторы принимают размер и необязательный вектор / список из n*n элементов.

## Тестирование

~~~sh
ctest --test-dir build --output-on-failure
~~~

- test/test_matrix.cpp — самостоятельные C++ юнит-тесты для обоих хранилищ
  и всех четырёх типов. Проверки работают и в Release.
- test/test_e2e.py — тесты CLI, случайных матриц по независимому эталону,
  ошибок ввода и переполнения. При наличии Python CMake регистрирует их в CTest;
  иначе сообщает, что E2E-тесты отключены.

Отдельный запуск:

~~~sh
./build/test_matrix
python3 test/test_e2e.py --cli ./build/matrix_cli -v
~~~

Краткие команды через Makefile: make, make test,
make run ARGS="array int 2" (элементы вводятся через stdin).
Makefile вызывает CMake и не содержит отдельной конфигурации компилятора.
